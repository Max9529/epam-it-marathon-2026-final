# Green & Tasty — EPAM IT Marathon 2026

Фінальний навчальний застосунок для **рівня 2: розгортання застосунку**. Фінальний тест проходить учасник окремо; цей репозиторій не означає, що тест уже складено або диплом отримано. Додаткова функціональність для рівня 3 не заявляється.

**[Відкрити сайт](https://dkkxdffz4660f.cloudfront.net)** · [API](https://0mkf7hi4d8.execute-api.eu-north-1.amazonaws.com/develop/locations)

Це демонстраційний ресторан: бронювання, ціни, адреси й дані меню використовуються для навчання. Реального ресторану, платежів та реальних замовлень немає. Для перегляду меню обліковий запис не потрібен. Для бронювання зареєструйте власного демонстраційного клієнта.

## Що входить

- Головна сторінка, популярні страви, деталі страв, меню з категоріями й сортуванням.
- Три демонстраційні локації, по шість столиків у кожній, шість позицій меню. Постійний каталог відокремлений від тимчасових AQA-даних.
- Реєстрація, вхід, вихід, профіль клієнта та перевірка фото профілю.
- Пошук столиків за локацією, датою, часом і кількістю гостей; створення та скасування бронювання.
- Окремий демоофіціант у кожній локації: Steve, Alice, Perlica. Їхні реквізити не є публічними та не потрібні клієнту.
- Відновлення пароля через email-код Cognito та перевірка email із профілю. Для відновлення потрібна попередньо підтверджена адреса. Неіснуючий і непідтверджений email отримують однакову відповідь; це не підтвердження фактичного надсилання листа.

## Локальний запуск інтерфейсу

Потрібні Node.js 22 відповідної версії з `package.json` і .NET 10 для серверних тестів.

```powershell
cd frontend/restaurant-frontend-app
npm ci
$env:BACKEND_URL = 'https://0mkf7hi4d8.execute-api.eu-north-1.amazonaws.com/develop'
npm run build
```

Production-збірка лежить у `dist/restaurant-frontend-app/browser`. `environment.production.ts` генерується зі змінної `BACKEND_URL` і не комітиться. `npm start` використовує окремий `environment.development.ts`: перед розробкою задайте в ньому URL свого API. Бекенд цього проєкту розрахований на AWS Lambda, локального HTTP-хоста в архіві немає.

## Тести

```powershell
# З frontend/restaurant-frontend-app
npx tsc -p tsconfig.app.json --noEmit
npx tsc -p tsconfig.spec.json --noEmit
npm test -- --watch=false

# З кореня репозиторію
dotnet test backend/restaurant-backend-app/Tests/APIHandler.Tests.csproj
```

Для Karma потрібен Chrome; для іншого місця встановлення задайте `CHROME_BIN`. Тестовий сервер прив’язаний **лише до 127.0.0.1**, дозвіл на доступ із домашньої мережі не потрібен. У GitHub Actions виконуються збірка та модульні тести; доступ до AWS для цього не надається. Реальний E2E-прогін зі створенням даних запускається окремо та не підміняється модульними тестами.

Фактичні результати та обмеження публікуються в [docs/verification.md](docs/verification.md). Наявність готового тесту не означає, що він пройшов; дивіться зафіксовані результати.

## Розгортання та доступ

Поточний сайт уже розгорнутий. У репозиторії немає паролів, AWS-ключів, сесій, Terraform state або локальних реквізитів офіціантів.

Для іншого AWS-акаунта потрібні власні тимчасові credentials, налаштування у `infra/terraform`, власні приватні state/artifact buckets і конфігурація Syndicate на основі `backend/restaurant-backend-app/config-example/`. Замініть прив’язані до поточного акаунта імена bucket-ів у Terraform. Не застосовуйте чужий Terraform state і не вмикайте платні ресурси без перевірки плану. Операційний стан і приватні сесії поточного розгортання до публічного коду не входять.

Автоматичного деплою з GitHub та нового постійного AWS-доступу для CI не налаштовано. Поточне оновлення виконується власником через тимчасову AWS-сесію. Початкові автоматичні deploy-workflow архіву не активовані в цьому репозиторії.

## Межі навчального проєкту

- Це навчальна демонстрація, а не production-система для роботи з реальними клієнтами.
- Успадковані групові сценарії не заявляються як завершена власна додаткова функція.
- Довга коректна адреса email на верхній межі 254 символи поки відхиляється початковою серверною валідацією; відомий дефект описано в роботі ДЗ8.
- Перевірка реального надходження email і завершення відновлення пароля залежить від налаштувань Cognito та підтвердженої адреси; у звіті вказано фактично перевірений обсяг.
- Успадковані бібліотеки мають попередження NuGet/збірки. Цей репозиторій не заявляється як такий, що пройшов повний аудит безпеки.
